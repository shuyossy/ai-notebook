# Microsoft Ignite 2026 まとめ

# 1. キーノートの要約

## 全体テーマ：「フロンティア・エコシステム」を支える3本柱

- Satya Nadella は今回のテーマとして、①急速に伸びる AI の能力をどう成果に変えるか、②その影響に対処する力を組織の中にどう築くか、の2つを挙げた。
- そのうえで、次の3本柱に沿って発表が行われた。
  - Human ambition（人の野心）：AI を、人の意図・判断・主体性を大きくする道具として仕事に組み込む
  - Intelligence（インテリジェンス）：各企業が自社の知識を AI の力として築き、所有し、改善し続ける
  - Trust（信頼）：AI は現時点では全面的には信頼できないため、AI に「何をさせてよいか」の権限を AI 自体から切り離して管理する

## 人の野心：Copilot が「仕事の OS」になる

- Copilot は、チャット・Cowork（複数の資料をまとめて作成する機能）・Code（自然言語でアプリやダッシュボードを作る機能）・Autopilot（24時間動き続ける自律型のエージェント）を1つにまとめた「仕事の新しい OS」と位置づけられた。Word・Excel・PowerPoint のフル機能も Copilot の中に取り込まれた。
- 今後数週間で、次の機能が順次展開される。
  - Today：メール・予定・Teams・会議・タスクを横断して重要事項を示し、下書きや予定変更の案まで用意して承認を待つ画面
  - Autopilot：テナント（Microsoft 365 の契約環境）内で動き、独自のメモリ・メールアドレス・コンピュータを持つ長時間稼働のエージェント
  - Workspaces：人とエージェントが共通のゴールと共有のコンテキストのもとで一緒に作業する場
  - ビジネスプラグイン：営業・法務・財務などの職種ごとに、スキルとコネクタをまとめて Copilot に追加する仕組み
- Salesforce との提携（Copilotforce）も発表され、Salesforce の顧客情報や操作を Copilot と Teams から扱えるようになる。
- GitHub では、複数のモデルを組み合わせて高い性能を低コストで出す GitHub Copilot Fusion が紹介された。

## インテリジェンス：自社のコンテキストとマルチモデル

- Microsoft IQ：企業のコンテキストを管理する仕組みとして発表された。Work IQ（Teams・メール・文書）、Fabric IQ（分析データ）、Foundry IQ（マニュアルなどのナレッジ）、Web IQ（Web 上の情報）を束ね、350以上のコネクタを持つ。
- マルチモデル：タスクごとに最も経済的なモデルを割り当てることが狙いとして示された。
  - Foundry では11,000以上のモデルを使える。質問の難しさに応じてモデルを振り分けるモデルルーターを使うと、すべて最上位モデルで処理する場合より最大65%安くなる。
  - 判断・分類に特化した Microsoft Decision 1.1 を正式提供した。一般的な LLM と比べて10倍以上速く、コストは200分の1である。
  - 自社モデル MAI の新モデル（コーディング向けの Code 2／Code 2 Flash、セキュリティ向けの Cyber 2 Flash）を発表した。顧客がモデルのウェイト（学習済みの中身）を入手して自社で管理できる「ライセンス済みウェイト」も提供する。
- 継続的な改善：Foundry 上で、評価 → 最適化 → 学習のループを回してエージェントを改善できる。

## 信頼：AI 資産の可視化・管理・保護

- Agent 365：エージェントの一元管理、展開の統制、エージェントごとのコストと価値の追跡を行う管理基盤である。管理対象のエージェントは5,000万を超え、Microsoft 以外（AWS、OpenAI、Anthropic、Google Cloud など）のエージェントにも対応する。
  - 事例：AT&T は6万を超えるエージェントを運用しており、各エージェントに固有の ID を持たせて管理している。90日使われていないエージェントの自動整理や、モデル変更によるコスト急増の検知も行っている。
  - Agent 365 Business Analytics（プレビュー）：AI への支出と、それが生んだ事業成果（完了した仕事）を結び付けて管理する。
  - 社員の PC 上で動く AI エージェントを65種類以上検出でき、管理外の「シャドー AI」の把握にも使える。
- サイバーセキュリティの前提の変化として、次の3点が示された。
  - 量：Microsoft の月例セキュリティ更新で対応した脆弱性が、1年足らずで100件未満から1,000件超へと10倍になった。
  - コスト：高品質な脆弱性の発見には約30万ドルの報奨金が必要だったが、今は AI で5ドル未満で見つかる（攻撃者も同様）。
  - 時間：脆弱性の発見から悪用までの時間がほぼゼロになった。
- Microsoft Perception：攻撃を模擬する Red、検知・調査する Blue、修正する Green の各エージェントで構成されるセキュリティ基盤を正式提供した。
- AI Transparency Initiative：AI の行動を検証し、許可範囲を制御するための業界標準づくりに取り組む（40以上の組織が参加）。

## インフラ

- エージェント向けに Azure を再設計した。分散型のデータベース HorizonDB の正式提供、自社開発の CPU Cobalt 200 の正式提供、国や地域ごとのデータ統制に対応するソブリンクラウドの選択肢などが発表された。

# 2. 全体を通しての所感

## 2-1. 関心は「AI を導入する」から「AI をどう管理し、育てるか」へ移った

- 3本柱のうち「信頼」は「おそらく最も重要」と位置づけられ、エージェントの一元管理・コスト管理・シャドー AI の検出など、管理面の発表に多くの時間が割かれた。6万を超えるエージェントを運用する AT&T のような企業も現れており、エンタープライズでは「AI を導入するか」の段階を過ぎ、「増えたエージェントをどう統制するか」が課題になっている。
- 統制の仕組みも具体的になってきている。エージェントに人と同じ ID を持たせてアクセス制御・監査・DLP（情報漏えい防止）を適用する仕組み、AI が生成したアプリを IT 部門が管理できる実行環境、社内で作られたアプリやエージェントを一覧して利用状況を確認できる管理画面などが、すでに提供され始めている。
- ここでいう管理には「統制」だけでなく「改善」も含まれる。本番で動くエージェントの実行記録（トレース）を材料に、「良い回答の基準を決める → 問題を見つける → 直す → 効果を確かめる」というサイクルを回す仕組みが整ってきており、実際にこのサイクルで品質スコアを68.6から83.3に上げた事例（NTT DATA）もある。AI エージェントは「作って終わり」ではなく、業務部門と IT 部門が品質の基準を決め、評価しながら育てていくものだという考え方が定着しつつあると感じた。

## 2-2. モデルは「どれが最強か」より「どう組み合わせて、コストを下げるか」

- モデルの性能競争そのものより、「同じ品質をどれだけ安く出せるか」に関心が移っていると感じた。質問の難しさに応じてモデルを振り分けるモデルルーター（最大65%のコスト削減）、判断・分類に特化した Decision 1.1、価格性能を重視した Microsoft の自社モデル MAI など、コストに関する発表が目立った。
- 代表例が GitHub Copilot Fusion である。AI エージェントのコーディング能力を測るベンチマークで、複数のモデルを組み合わせることにより、単一の最上位モデルより高いスコア（71.2%）を、大幅に低いコスト（最大88%減）で出した。モデルを大きくしても品質の上限は頭打ちになるが、苦手な部分の異なるモデルを組み合わせれば上限が上がる、という結果は印象的だった。現状では、こうしたモデルルーティングや組み合わせが、品質とコストを両立させる有力な手段だと考えられる。
- 当行でも、「最新・最上位のモデルを使えばよい」という発想から、タスクごとの使い分けを前提に、品質とコストを実際の利用パターンで評価する発想へ切り替えていく必要があると考えられる。

## 2-3. 出力の質を左右するのは「どれだけ良いコンテキストを与えられるか」

- AI モデル全体の性能が上がった今、差がつくのは AI に渡す情報（コンテキスト）の質である、というメッセージが今回最も繰り返し語られたと感じた。Microsoft IQ やビジネスプラグインの発表に加え、「コンテキストは顧客の知的財産である」という発言もあった。
- Copilot の裏側で社内の情報を AI に渡す Work IQ も強化され、使う人の好み（Memory）、仕事・人・組織のつながり（Context）、定型作業の手順（Skill）を AI に渡せるようになった。また、業務アプリの画面を開かずに Copilot から横断的に操作する「ヘッドレス」な使い方が今後主流になる、という見立ても示された。これも、業務データを AI が安全に扱える状態に整えておくことが前提になる。
- 自分自身や当行においても、「仕事の情報をどこに集約し、それを AI のコンテキストにどう反映させるか」が、AI 活用と精度向上の鍵を握りそうである。

## 2-4. AI でコードが増えるほど、脆弱性を「持ち込ませない」仕組みが重要になる

- AI によるコーディングの浸透に伴い、セキュリティの懸念も急速に高まっている。GitHub 上のコード量が爆発的に増え、同じ種類の脆弱性の報告は前年の3.9倍、OSS に紛れ込んだマルウェアは脆弱性の約8倍に達した。さらに AI によって脆弱性の発見コストが大きく下がり、発見から悪用までの時間はほぼゼロになった。攻撃側・防御側ともに「AI の速度」で動く時代になったといえる。
- 対策として一貫していたのは「後片付けより予防」という考え方である。GitHub のセキュリティ機能群（GHAS：GitHub Advanced Security）も、問題のある OSS を取り込ませない仕組み（パッケージファイアウォール）、パスワードなどを含むコードのアップロードを止める仕組み（プッシュ保護）、コミット前の AI によるセキュリティレビューといった「リモートリポジトリに脆弱性を持ち込ませない」機能を軸にしている。それでも入り込んだものはスキャンで検知し、AI エージェントに修正させる、という構成である。
- 当行においても、AI 駆動開発の標準スキルや GitLab の CI/CD パイプラインを活用し、脆弱性を「持ち込ませない」「持ち込まれても検知する」「最終的に本番環境に持って行かせない」仕組みを作ることが重要になると考えられる。特に、パッケージを自律的にインストールするコーディングエージェントを使う場合は、OSS の取り込み口での検査（マルウェアのブロックや、公開直後のバージョンを一定期間使わないクールダウンなど）も検討すべきである。
